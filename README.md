# FIN Analyzer

**FIN Analyzer** — browser-first платформа финансового анализа, работающая без обязательного Backend и серверной базы данных.

## Продуктовая концепция

Пользователь выбирает тип финансового отчёта, скачивает версионированный XLSX-шаблон FIN, заполняет его и загружает обратно. Альтернатива — заполнение той же формы непосредственно в React. Данные проходят детерминированную бухгалтерскую и структурную проверку, после чего FIN рассчитывает финансовые показатели, применяет настраиваемые стратегии и строит интерактивные диаграммы и отчёты.

**Принцип:** никакое AI-распознавание произвольных PDF/Excel не переносит непроверенные показатели в утверждённый анализ.

## Технический контур MVP

- React + TypeScript + Vite; SPA с возможностью последующей офлайн-доставки (PWA).
- Apache ECharts для интерактивных визуализаций.
- ExcelJS для экспорта/импорта контролируемых XLSX-шаблонов.
- decimal.js для финансовых расчётов.
- В R1A используется React state и доменная проверка; Zustand и Zod запланированы при расширении проекта.
- Сохранение и восстановление проекта через локальный JSON-файл. База данных и сетевой API не требуются.
- Quarto рассматривается **после MVP** как опциональный внешний генератор отчётов, не как браузерная библиотека.

Остальные формы, стратегии, Quarto, PDF и PWA пока не реализованы. Для подробностей см. [R1A Status](docs/FIN-R1A-STATUS.md).

## Локальный запуск

Требуется Node.js 22+.

```bash
npm install
npm run dev
```

Проверки:

```bash
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

В браузере: ввести компанию → скачать шаблон «Бухгалтерский баланс» → заполнить голубые ячейки → загрузить XLSX → проверить ошибки → утвердить → посмотреть диаграммы → сохранить `.fin.json`.

Пользовательские финансовые данные по умолчанию не отправляются на сервер. **Автосохранение отсутствует:** скачивайте `.fin.json` для резервной копии. Режим offline/PWA после первого визита ещё не реализован.

## Принципы разработки

1. Все финансовые значения имеют тип, валюту, масштаб, период, источник и статус проверки.
2. Отсутствие показателя не равно нулю.
3. Ошибочная загрузка не меняет последнюю утверждённую ревизию.
4. Новые формы, стратегии и индикаторы описываются версионируемыми декларативными конфигурациями.
5. Расчёты детерминированы, прослеживаемы до исходных ячеек и закреплены автоматическими тестами.
6. Один репозиторий; не создавать ветки без реальной необходимости.

Лицензирование продукта и право использования внешних источников отчётности требуют отдельного решения.
