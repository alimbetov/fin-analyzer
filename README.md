# FIN Project Marketplace

**FIN Project Marketplace — основная B2B-платформа для компаний, экономических проектов, инвесторов, банков, консультантов и партнёров. FIN Analyzer — встроенный модуль финансово-экономической диагностики и интерпретации показателей.**

Представитель бизнеса — от предпринимателя без бухгалтера до финансового директора крупной компании — выбирает цель анализа и удобный способ ввода. FIN помогает собрать нужные показатели, проверяет согласованность данных, рассчитывает доступные метрики и объясняет результаты. Для недостающих данных предлагается следующий полезный вопрос — без выдуманных чисел и необоснованных оценок.

> **Главный продуктовый документ: [FIN Analyzer — проектное ТЗ v3.6](docs/FIN-ANALYZER-PROJECT-TZ.md).** Содержит миссию, S0–S4, FIN-B1…B5, адаптивные сценарии, финансовое ядро, результаты, дорожную карту и критерии приёмки.

## Модули платформы

**FIN Analyzer** — экономический движок и интерпретатор. **«Мой бизнес»** — продажи, эффективность и отчётность. **«Мой проект»** — стратегия и инвестиционные бизнес-планы. **Project Discovery** — публикации проектов и поиск партнёров. **FIN Connect** — кабинеты, обращения и взаимодействие. **Report Center** — публикация отчётности. **Access Center** — доступ по зонам, срокам, контрактам, одному просмотру/скачиванию и отзыв прав.

[ADR-010 — название платформы](docs/ADR-010-PRIMARY-PRODUCT-NAME.md) · [ADR-009 — управляемый доступ](docs/ADR-009-REPORT-ACCESS-ZONES.md).

## Пользовательские сценарии

| Профиль | Как работает FIN | Что получает |
|---|---|---|
| S0 — новый бизнес | запланированные продажи, затраты, стартовый капитал | расчётные сценарии, не историческую прибыль |
| S1 — микробизнес / ИП | короткие вопросы простыми словами | экспресс-анализ и ограничения |
| S2 — малый бизнес | продажи, расходы, деньги, долги, товары | диагностику прибыльности и cash |
| S3 — компания с учётом | полные формы F01–F04 и расшифровки | финансовые коэффициенты и динамику |
| S4 — группа компаний | отдельная отчётность и корректные элиминации | групповой анализ при достаточных данных |

Профиль выбирается по сложности и задачам бизнеса, **не только по юридической форме**.

## Направления экономического анализа

Базовые направления: **финансы, инвестиции, маркетинг, производство/операции и конструктор бизнес-планов**. Дополнительно проектируются 12 модулей: Funding & Capital Raising, FIN Project Marketplace, Business Valuation, Sales & Commercial Analytics, Procurement & Supply Chain, HR & Workforce Economics, Tax & Regulatory Planning, Strategic Planning, Risk Management, Partnerships & Franchising, Project Execution & Monitoring, Sustainability & Resource Economics.

[Каталог направлений, проектные требования и условия реализации](docs/ECONOMIC-DIRECTIONS.md). Особое правило: локальное создание и экспорт проекта не равнозначны работе онлайн-маркетплейса; публикация, поиск инвесторов и Data Room требуют отдельного hosted-контура и проверенной модели доступа.

## FIN Project Marketplace — принятое позиционирование

**FIN Project Marketplace** — будущая B2B-площадка публикации экономических проектов, поиска инвесторов, банков и деловых партнёров, запросов информации и обмена разрешёнными материалами. **Это не инвестиционная биржа. FIN не проводит финансовые операции, не принимает/не хранит/не переводит деньги, не организует торги и не исполняет инвестиционные сделки или договоры.** Участники действуют и рассчитываются вне платформы.

В локальном FIN Core можно готовить бизнес-план и безопасный экспорт; онлайн-каталог и обмен требуют будущего отдельного сервера FIN Connect. Публикация проектов с инвестиционной составляющей должна пройти применимую страновую юридическую проверку даже при отсутствии платежей.

[ADR-007 — официальное название и продуктовые границы](docs/ADR-007-FIN-PROJECT-MARKETPLACE.md).

## Выбранный стек FIN Connect (планируемый hosted-контур)

React + TypeScript → **Spring Boot Backend/BFF** → закрытые сервисы **Keycloak + Redis + RustFS + KumoMTA + PostgreSQL**. React не подключается к Redis, RustFS, KumoMTA, PostgreSQL или административному API Keycloak и не хранит OAuth-токены. Вход выполняется через контролируемые reverse proxy auth endpoints Keycloak, сессии и токены находятся на сервере. PostgreSQL — постоянные данные, Redis — сессии/временный кэш, RustFS — приватные документы, KumoMTA — почтовая доставка.

[ADR-008 — техническая архитектура backend и интеграций](docs/ADR-008-FIN-CONNECT-BACKEND-STACK.md). Это **спецификация**, а не реализованный backend. Локальный FIN Core продолжает работать без сервера.

## Пользовательские рабочие пространства

- **Мой бизнес:** продажи, деньги, запасы, эффективность, диагноз внутренних проблем через прозрачный интерпретатор; отдельная возможность публикации финансового отчёта.
- **Мой проект:** стратегические планы, альтернативы, инвестиционная модель и бизнес-планы, подготовка пакетов для инвестора, банка и партнёра.
- **FIN Project Marketplace:** добровольная публикация выбранной карточки проекта, поиск, запросы интереса, адресные документы и партнёрства.
- **Консалтинговая компания:** отдельный участник с собственной командой и кабинетом; после согласия другой компании запрашивает **дополнительные материалы сверх форм отчётности** и готовит заключения на основании ограниченно переданных документов.

Роли, панели и мастера: [Workspaces & Journeys](docs/FIN-WORKSPACES-AND-JOURNEYS.md) · [Мой бизнес](docs/FIN-MY-BUSINESS-INTERPRETER.md) · [Мой проект](docs/FIN-MY-PROJECT-STRATEGY.md) · [Отчёты](docs/FIN-FINANCIAL-REPORT-PUBLICATION.md) · [Консалтинговая компания](docs/FIN-CONSULTING-COMPANY-DOCUMENT-REQUESTS.md).

Все новые функции — **PLANNED**, без утверждения о существующих кабинетах или интеграциях.

## Способы ввода

- **FIN-B1:** Smart Interview и Express Check — первыми для простого старта.
- **FIN-B2:** React-таблицы, версии шаблонов Excel, вставка диапазонов.
- **FIN-B3:** журнал бизнес-операций.
- **FIN-B4:** контролируемый импорт CSV, выгрузок банков, кассы и учётного ПО.
- **FIN-B5:** необязательные голосовые и OCR-черновики с подтверждением человеком.

Разные способы ввода должны вести к единой канонической финансовой модели, без двойного учёта.

## Архитектурная база

- React + TypeScript + Vite, browser-first; без обязательного Backend или серверной БД на первом этапе.
- Apache ECharts для визуализации, ExcelJS для контролируемых XLSX, decimal.js для финансовых вычислений.
- Детерминированная валидация, типизированные формулы и версии методик.
- Локальный проект `.fin.json`, возможность последующей offline/PWA-доставки.
- Quarto — потенциальный необязательный внешний генератор профессиональных отчётов, не зависимость браузерного MVP.

## Основные принципы

1. Данные с неизвестным значением не заменяются нулём; `MISSING`, `EXPLICIT_ZERO`, `NOT_APPLICABLE`, `ESTIMATED` различаются.
2. «Продали» не тождественно «получили деньги»; закупка товара не тождественна себестоимости реализации; кредит и вклад собственника не являются выручкой.
3. Каждый результат объясняется источниками, формулами, периодом, валютой, методикой и ограничениями.
4. Финансовая диагностика — помощь в принятии решений, а не подтверждение аудита и не гарантия кредитования.
5. Одна финансовая модель поддерживает и короткий мастер для ИП, и профессиональные формы компании.
