## 2. Four independent acceptance levels

1. **REGISTRY VALIDATED** — source table registered, has known parent/schema, no duplicate or invalid field. This is not a KPI pass.
2. **ARITHMETIC GOLDEN GREEN** — numerical baseline and controlled input substitution reproduce independent expected numbers. No fabricated risk or causality.
3. **METHODOLOGY APPROVED** — formula/period/units/scope/thresholds independently reviewed for a stated business model and legal regime.
4. **TRUSTED E2E ACCEPTED** — Keycloak/ABAC + published PostgreSQL fact revisions + scenario engine + React + manual Desktop UAT + single-SHA CI.

The 14-method Java smoke and 9-form JS smoke target level 2; all 30 EX sheets are at least covered by *test definitions* for level 1, pending CI. Level 3/4 remain blocked.

**All figures are synthetic and scoped to the listed metric, with no implied unit interoperability.** NPV is a mathematical approximation with ACT/365 and a pinned discount policy, not investment approval. DSCR is not a lender-qualified covenant calculation. Budget variance sign is not automatically favorable or unfavorable.

For each method, `ScenarioFiveQuestionEngine` returns:
- **What:** exact numeric result + method version + source row IDs/revisions.
- **Why:** a named rule reason, explicitly `HYPOTHESIS_ONLY` or blocked if inputs missing.
- **Seriousness:** `NOT_ASSESSED` until materiality/risk policy independently qualified.
- **Action:** a source-linked candidate review instruction, `REVIEW_REQUIRED` for observed anomalies, `REVIEW_SUGGESTED` otherwise; human approval required.
- **Effect:** `SIMULATED_ONLY`, exact hypothetical input changes, before/after/delta; not ROI, cost of implementation, sensitivity bands, inaction forecast or causal proof.

The wrapper rejects changed source identities, organization/scope, periods, schemas and unchanged alternatives. It cannot evaluate customer `ACTUAL` data. Its `APPROVED` flags are synthetic test assumptions, never frontend authority.

## 4. Mandatory form-by-form smoke matrix

Every one of 166 top-level forms has an entry. All 54 sector forms without code have a dedicated negative test that must reject fake calculation rather than synthesize an unsupported KPI. The 22 unimplemented EX numerical methods remain schema-only and must never be shown as calculated financial findings.

`smoke-cli.mjs` groups forms by:
- `sectorSmokeStatus`: `EXECUTED_SYNTHETIC_ONLY` or `NOT_EXECUTABLE_IN_SECTOR_KERNEL`
- `javaScenarioStatus`: `GOLDEN_TEST_DEFINED_CI_MUST_VERIFY` or `NOT_DEFINED`
- EX sheet `status`: `GOLDEN_TEST_DEFINED_CI_MUST_VERIFY` or `CONTRACT_TEST_DEFINED_ONLY`

The statuses are intentionally non-interchangeable. A form can lack an SF numerical calculator but have a separate Java scenario case.
