## 1. Решения, которые приняты редакционно

| Код | Область выбора | Решение FIN | Важный контроль |
|---|---|---|---|
| P0-1 | Организация/проект/план | МСФО и управленческие результаты отдельно; общие неизменяемые первичные данные | Запрет смешивания accounting basis в одном CalcPlan; отдельные adjustments и версии |
| P0-2 | Конкретное обязательство / asOf | Готовый баланс + независимая проверка, если движения доступны | Без журнала операций режим `SOURCE_ONLY`, не заявлять реконструкцию; не вычитать оплату дважды |
| P0-3 | Класс финансового инструмента/портфель | Сначала IFRS 9 simplified provision matrix для допустимых торговых требований; затем общий ECL/PD-LGD-EAD | Нельзя произвольно выбирать метод для инструмента; несколько допустимых сегментов могут иметь разные политики без смешивания внутри одной экспозиции |
| P0-4 | Класс запасов (характер + использование) | Последовательное FIFO/средневзвешенная для взаимозаменяемых; специфическая идентификация для невзаимозаменяемых | IAS 2 применимость; смена формулы — новая политика и доказанное основание |
| P0-5 | Кредитный договор + accounting basis | Два разных представления: договорные cash payments и начисления/остатки по EIR | EIR interest expense не подменяет денежные проценты; **не утверждать тождество сумм процентов/погашения по двум графикам** |
| P0-6 | Проект и сценарий | Независимый выбор DCF: FCFF + WACC => EV, FCFE + Ke => Equity Value | Эквивалентность сравнения требует EV-to-Equity bridge и одной базы/момента/версии сценария |
| P0-7 | Кредит и ковенант | По договору считать covenant DSCR; аналитический DSCR — отдельно | Если договор не определяет CFADS/debt-service, нельзя автоматически подтверждать соблюдение ковенанта по аналитической формуле |
| P1-1 | Основное средство/компонент | Поддержка отдельных существенных компонентов | Сроки, стоимости, компоненты, критерий существенности из версии политики |
| P1-2 | Консолидация денежных потоков | Один источник денежных операций; прямой/косвенный CFO — разные представления | Сверка строго по одному периметру, валюте, периоду и редакции, с неденежными/FX корректировками |

## 2. Предложение P1-3: политика параметров — не утверждена численно

| Ключ параметра | Пример из источника | Решение FIN |
|---|---|---|
| `materiality_threshold` | 0,5% от активов или выручки (большая база) | **Только предложение**, выбор базы/процента требует собственника политики и S2 |
| `rounding_precision` | 2 знака | **Не глобальное значение:** валюта, учётная единица, измерение и исходная точность могут отличаться |
| `fx_rate_source` | Курс закрытия FactSet | **Не всегда допустимо:** дата/источник/монетарность/историческая оценка зависят от экономической статьи |
| `reconciliation_tolerance` | 0,1% или минимум 1 000 | **Только предложение**; сочетание абсолютного и относительного порога должно быть задано явно |
| `reconciliation_tolerance_p0` | 0 для C01/C02 | **Запрашивается финансовое утверждение**, хотя для точного хеша/источника технически допускается строгая нулевая толерантность |

Правило исполнения: нет подтверждённого базового значения — `RECONCILIATION_TOLERANCE_POLICY_UNAPPROVED`; form override может только ужесточать явно утверждённое значение. Нельзя молча применять приведённые цифры ко всем 166 формам.

## 3. Поправки к исходному материалу

- **P0-5:** одна договорная денежная операция может фигурировать в обоих представлениях, но сумма «денежного потока по бухгалтерскому графику» не должна автоматически сравниваться с EIR начислениями: это разные величины. Сверять строго обозначенные cash components и учётный roll-forward.
- **P0-3:** запрет «смешивания в одной форме» слишком широк: ответственность лежит на политике **класса инструмента/сегмента** и уникальной экспозиции; IFRS 9 предусматривает разные области упрощённого подхода.
- **P0-7:** при отсутствии определения в договоре аналитический DSCR доступен лишь с маркировкой `ANALYTICAL_DSCR_NOT_COVENANT`, без статуса compliance.
- **P1-2:** равенство CFO прямого и косвенного способов имеет смысл для одной отчётной базы с полными корректировками; не сводить его к `NI+depreciation-deltaNWC` без учёта классификаций и неденежных событий.
- **P1-3:** числовые пороги не являются требованиями IFRS; пользователь предложил возможные настройки, а не независимое финансовое S2.

Справочно:
- IAS 2 (официально): https://www.ifrs.org/issued-standards/list-of-standards/ias-2-inventories/
- IFRS 9: https://www.ifrs.org/issued-standards/list-of-standards/ifrs-9-financial-instruments/
- IAS 7: https://www.ifrs.org/issued-standards/list-of-standards/ias-7-statement-of-cash-flows/

2. Миграция `055-fin-calc154-p0-p1-editorial-policy-decisions.sql`: 10 immutable policy decisions с точными источниками, версией, областью применения, выбранным правилом, нормативно/финансовыми блокировками, типизированной JSONB evidence, SHA-256, `financial_s2_approved=false` и `production_admitted=false`.

Реестр не является внедрённым пользовательским селектором методики и не прикреплён автоматически к runtime `CalcPlan`. Для этого нужен следующий этап.

## 5. Дальнейшая интеграция (после технической приёмки)

**R1 — Policy Resolution:** versioned hierarchy `SYSTEM -> ORGANIZATION -> PROJECT -> SCENARIO -> INSTRUMENT_CLASS/CONTRACT/INVENTORY_CLASS -> FORM`, с явными правилами приоритета без размывания обязательных ограничений. Сохранять **конкретную policy revision** и SHA, а не подставлять «последнюю» в момент выполнения.

**R2 — Application Binding:** связать FIN CALC-A01…A06, источники fin_intake/fin_fact и параметризованную политику в одном immutable `CalcPlan`. Для A01 различать исходный готовый остаток и реконструированный; для A05 два раздельных графика, но общие договорные cash events; для A06 FCFF/FCFE сценарные варианты.

**R3 — Explainability:** у каждого расчёта есть исходные FactSetId, sourceRevisionId, methodRevisionId, policyDecisionRevisionId, валюта, период, сырой и округлённый результат, контрольный пример и reconciliation status.

**R4 — S2 & production:** сначала независимая финансовая экспертиза всех обязательных вариантов/границ, затем отдельное production admission с отозванием и stale guards.

## 6. Что необходимо подтвердить дополнительно

1. Один обезличенный invoice с частичным погашением и корректировкой срока (A01).
2. Один кредитный договор с fee, фактическими cashflow датами, EIR и определением covenant CFADS/debt service (A05/P09).
3. Политика IAS 2 для двух классов запасов: interchangeable и non-interchangeable, вместе с примером изменения метода (A03).
4. Для P07 один полностью датированный FCFF-сценарий с WACC, terminal assumptions и отдельным EV/Equity bridge, либо FCFE с Ke.
5. Утверждённый профиль по валютам, единицам, существенности, абсолютным/относительным допускам и basis-specific FX — **без неаргументированных универсальных процентов**.

Эти данные нужны для полноценной E2E-квалификации, не для простого создания следующей редакции справочника.
