# ADR-007 — FIN Project Marketplace: информационная B2B-площадка, не финансовая биржа

**Дата:** 2026-11-15  
**Статус:** ACCEPTED — продуктовая граница и официальное наименование; реализация **PLANNED / NOT IMPLEMENTED**  
**Решение:** в качестве официального имени каталога деловых и инвестиционных проектов используется **FIN Project Marketplace**; отказ от финансовых операций и биржевых торгов является постоянным ограничением продукта.

## 1. Product definition

**FIN Analyzer** — система финансового и экономического анализа, создания бизнес-планов и оценки проектов. **FIN Project Marketplace** — связанный с ней информационно-коммуникационный B2B-модуль для размещения проектов и поиска инвесторов, банков, фондов, поставщиков ресурсов, консультантов и деловых партнёров.

Функция Marketplace — помочь представить проект, проверить доступную экономическую информацию, найти релевантные организации, согласовать предоставление дополнительных материалов и начать коммуникацию. Пользователи самостоятельно заключают договоры и осуществляют любые платежи, инвестиции или иные юридически значимые действия **вне FIN**.

FIN не является организатором торгов, биржей, брокером, дилером, депозитарием, кастодианом, платёжным агентом или кредитором только в силу реализованных функций каталога. Отсутствие денежных переводов не гарантирует отсутствие регуляторных обязательств: характер рекламы финансовых инструментов, инвестиционных предложений, посредничества и схем вознаграждения требуется оценивать отдельно в каждой юрисдикции **до** запуска соответствующих возможностей.

**Уточнение для консалтинга:** FIN Project Marketplace также может соединять консалтинговые компании с бизнесом. После обоюдно принятого сотрудничества консультант может запросить дополнительные материалы, включая документы вне финансовых форм, и подготовить информационное заключение. Запрос **не даёт автоматического доступа** к сведениям клиента, а оплата/договоры выполняются вне FIN. [Детальное ТЗ](FIN-CONSULTING-COMPANY-DOCUMENT-REQUESTS.md).

## 2. Явно разрешённые возможности

- Создание, финансовая проверка и версионирование EconomicProject / EconomicCase / BusinessPlanCase.
- Выпуск ограниченного публичного инвестиционного паспорта (PublicTeaserSnapshot), отдельного от исходной частной модели.
- Поиск, фильтрация и сравнение проектов по заявленным параметрам и методикам, без гарантированных обещаний доходности.
- Запрос интереса (InterestRequest), приглашение для общения, запрос документа, предварительная запись встречи.
- Конфиденциальный обмен файлами по разрешению владельца, Data Room и журнал доступа **только в будущем hosted FIN Connect**.
- Отображение желаемых источников финансирования и характеристик проекта (сумма, валюта, назначение, сроки) **только как информационных параметров**.
- Отображение результата внешнего соглашения или поступления инвестиций **только как задокументированного вручную/проверенного внешнего факта**, без проведения финансовой операции.
- План-факт выполнения проекта и инвестиционные отчёты по согласованному набору сведений.

## 3. Категорически вне scope FIN

- Приём, хранение, перевод или распределение денежных средств пользователей, инвестиционных взносов и кредитов.
- Расчётно-платёжные счета, электронные кошельки, escrow и custody.
- Сбор денежных обязательств, резервирование/списание средств, внутренний инвестиционный баланс.
- Ордербук, встречные заявки на торговлю финансовыми инструментами, matching/trade execution, клиринг, биржевые и внебиржевые сделки, расчётно-депозитарная инфраструктура.
- Размещение, продажа, подписка и фактическое приобретение ценных бумаг **через FIN**, а также автоматическое заключение договора или юридически обязательная акцептация инвестиционного оферты.
- Выдача кредита, автоматическое кредитное одобрение или гарантирование доходности/возврата инвестиций.
- Переход к регулируемому инвестиционному посредничеству/краудфандингу как «поздняя фаза» текущего продукта: это **не часть целевого roadmap** FIN.

В интерфейсе не использовать вводящие в заблуждение CTA: «Купить долю», «Вложить деньги сейчас», «Оплатить инвестицию», «Исполнить сделку», «Биржевые торги», «Оформить кредит в FIN». Допустимы «Изучить проект», «Запросить информацию», «Связаться», «Пригласить к обсуждению», «Скачать разрешённый пакет».

## 4. Контуры и границы данных

**Технологическая архитектура будущего FIN Connect зафиксирована в [ADR-008](ADR-008-FIN-CONNECT-BACKEND-STACK.md):** React → Spring Boot BFF → закрытые Keycloak/Redis/RustFS/KumoMTA/PostgreSQL. Браузер видит лишь UI Keycloak через контролируемый reverse proxy. Прямые клиентские вызовы к приватным хранилищам, очередям, почтовой инфраструктуре и admin API запрещены.


| Контур | Цель | Техническая граница |
|---|---|---|
| FIN Core | локальные расчёты, Business Plan Builder, репорты | статический React/TypeScript, без обязательного сервера/авторизации |
| FIN Share | локальный просмотр и экспорт безопасного пакета проекта | пользователь явно контролирует состав перед передачей |
| FIN Project Marketplace / FIN Connect | hosted каталог, регистрация организаций, роли, поиск, сообщения, разрешённые файлы, Data Room | отдельный серверный контур; IAM, tenant isolation, RBAC/ABAC, audit, abuse protection |
| Внешние учреждения и участники | банковское рассмотрение, договор, перевод средств, инвестирование | **полностью вне FIN**, статус в FIN — только ссылка/подтверждение, никакой execution |

ProjectOwner и организация не обязательно одно лицо. Права представительства в hosted сервисе требуют отдельной процедуры подтверждения; паспорт и личные сведения не публикуются по умолчанию.

## 5. Статусы взаимодействия

**Project**: DRAFT → OWNER_APPROVED_FOR_SHARING → PUBLISHED → UNPUBLISHED/ARCHIVED.

**InterestRequest**: CREATED → SENT → RESPONDED/DECLINED → CLOSED.

**DocumentRequest**: REQUESTED → GRANTED/DENIED → ACCESS_EXPIRED/REVOKED.

**ExternalAgreementReference**: user-reported, attached evidence status UNKNOWN/UNVERIFIED/VERIFIED_EXTERNAL_REFERENCE; статус не является заключением договора внутри FIN.

Статусов **ORDER_PLACED, INVESTMENT_PAID, TRADE_EXECUTED, SETTLED** в FIN Marketplace быть не должно. Никакой \`InterestRequest\` не означает принятие финансового обязательства.

## 6. Раскрытие и безопасность

- Принцип *deny-by-default*: публичная карточка — allowlisted поля, никаких full \`.fin.json\`, исходных банковских файлов, зарплатных ведомостей, секретов, персональных данных и скрытых метаданных.
- Preview публикуемого документа + явное подтверждение владельца и versioned snapshot.
- Для hosted-доступа: scoped permissions, назначенный получатель, expiry, revocation, журнал просмотра/выдачи.
- Отзыв доступа прекращает будущую выдачу, **но не уничтожает уже скачанную копию**.
- Модерация подложных проектов, жалобы, источники данных, антиспам, запрет необоснованных обещаний доходности.
- Перечисление проектов и контактные формы проходят отдельную юридическую проверку по каждой стране перед запуском; отсутствие платёжной функции не снимает автоматически всех требований.

## 7. Условия приёмки

| ID | Проверка |
|---|---|
| MKT-01 | Сценарий owner→public preview→publish требует явного согласия, версия фиксируется |
| MKT-02 | Публичная карточка не содержит private facts/PII/financial accounts и исходный FIN-проект |
| MKT-03 | Investor/bank/partner видит только явно разрешённую проекцию и запрашивает информацию, а не инвестирует внутри FIN |
| MKT-04 | Нет UI, API, событий, сущностей или платежных провайдеров, реализующих торговлю или перевод денежных средств |
| MKT-05 | InterestRequest не создаёт юридического договора, оплаты или инвестиционного баланса |
| MKT-06 | ExternalAgreementReference содержит происхождение, дату, статус проверки и не выдаётся за FIN-executed transaction |
| MKT-07 | Межорганизационная изоляция, протоколы выдачи/отзыва, журналы доступа и негативные security E2E |
| MKT-08 | Термины FIN Project Marketplace, Investor Discovery, Project Listing используются согласованно во всех интерфейсах и ТЗ |
| MKT-09 | Риск регулирования публикации/представления инвестиционных проектов рассмотрен для целевой юрисдикции до публичного hosted запуска |

**Текущее доказательство:** это принятое продуктовое решение и ТЗ. В GitHub действующий код пока содержит только F01 Balance прототип (Draft PR #2), **FIN Project Marketplace не реализован**.

## 8. Контроль изменения решения

Любая инициатива добавить торговлю, приём денег, инвестиционные расчёты между пользователями или исполнение финансовых договоров является **новой продуктовой концепцией**, не расширением существующего FIN Marketplace. Для неё потребуется самостоятельная юридическая, финансовая, архитектурная и продуктовая квалификация, а также отдельное одобрение владельца проекта; она не наследует разрешения этого ADR.
