# FIN R19 — Versioned Import Profile / Preview → Commit

Branch: `feat/fin-form-library-standalone`  
Status: **CODE COMMITTED / EXECUTION HOLD**. No Maven or PostgreSQL GREEN evidence.

## Purpose and ownership

A server-side, immutable import descriptor belongs to `fin_lib`. A short-lived preview ticket belongs to `fin_ui`. No financial values are persisted by either one. Only existing `FormDraftService.save` writes a new `fin_intake` revision.

The current version supports **only FIN XLSX V2** files generated by the existing two-sheet `REPORT` + `PARAMETERS` export. This is NOT an arbitrary spreadsheet parser, not an approved external mapping profile, and not a full conversion of the independent `ReportGridService` writer. The server independently validates field codes, types, units, requiredness and exact source form version. The `PARAMETERS` worksheet is untrusted source metadata.

## Database

- `017-lib-versioned-import-profile.sql` adds `fin_lib.lib_import_profile_version` (keyed by UUID; unique form version, code and integer version; SHA-256 + JSON descriptor; state `LOCAL_TEST_ONLY`) and `fin_ui.lib_import_preview_ticket` (source instance, organization, revision, content SHA, file SHA, profile SHA, expiry).
- `018-lib-import-profile-postgresql-immutability.sql` rejects UPDATE/DELETE for profiles in PostgreSQL using existing function from migration 015.
- `register` is idempotent when the computed descriptor is unchanged, else appends a new profile version. The descriptor is derived exclusively from server-pinned `FormVersion` and `FormField`, never from XLSX.
- Profile reads cross-check the recorded SHA with both the stored JSON and the live server descriptor, rejecting any stale or modified schema.

## API (local development only)

1. Register local profile version:
   `POST /api/v1/import-profiles`

   ```json
   {"formVersionId":"<existing form version UUID>"}
   ```

2. Preview (multipart, no report write):
   `POST /api/v1/import-profiles/{profileId}/preview`

   Multipart fields: `instanceId`, `organizationId`, `file`, `actor`, `reason`.

   Result: `previewId`, profile/form context, `expectedRevision`, `uploadSha256`, `bindingSha256`, `expiresAt`, parsed values and total field count. Preview tickets expire after 15 minutes. Preview performs structural validation and the existing `FormDraftService` canonical type/requiredness validation without writing financial values.

3. Commit (multipart, re-upload exact file):
   `POST /api/v1/import-profiles/previews/{previewId}/commit`

   Multipart fields: same instance, organization, file, actor, reason plus `Idempotency-Key` header.

   Server locks the preview ticket, verifies identity, TTL, exact file bytes SHA, immutable profile SHA, expected revision and source content SHA; parses and validates again, calls the existing draft writer, then consumes the ticket. Writes and ticket consumption happen in one transaction.

4. Existing direct `POST /api/v1/drafts/{instanceId}/import.xlsx` remains available for backward compatibility in this isolated prototype. **It bypasses R19 preview**, so it must be retired or admission-gated before any production release. No public deployment without IAM.

## Safety constraints

- Two-sheet canonical import only; unknown columns, formulas and changed PARAMETERS are rejected.
- Same template + source data snapshot is preserved across CLASSIC/EXCEL/DASHBOARD representations.
- No configurable expressions, arbitrary SQL, unsafe formulas, fuzzy column mapping or locale guessing.
- Profile state `LOCAL_TEST_ONLY` does not mean S1/S2 financial approval.
- File upload limit is 2 MB; content parsing bounded by the existing XLSX field limit. Server currently reads the entire workbook into memory; separate ZIP-decompression limits and container resource restrictions are necessary before exposing public ingestion.
- User IDs and author names are still supplied by callers. The branch has no Spring Security. Do not deploy outside localhost.
